# Future Auto Services — الإصدار الأول 1.0.0

موقع Future Auto Services لخدمات فحص السيارات وتشخيصها والاستشارات الفنية. البناء ما زال كما هو: HTML مستقل لكل صفحة، CSS وJavaScript Vanilla مشتركان، بدون Framework أو Backend أو Database أو خطوة Build.

## التشغيل

```bash
python3 -m http.server 3000
```

ثم افتح `http://localhost:3000`.

## الهوية والتصميم

- الهوية الأساسية في كل نقاط الظهور هي **Future Auto Services**.
- اسم المهندس موجود داخل صفحة «من نحن» كجزء تعريفي فقط، وليس كاسم المركز في الهيدر أو الفوتر.
- اللوجو المستخدم موجود في `assets/images/future-auto-logo-transparent.webp`، مع fallback إلى `assets/images/future-auto-logo.webp`.
- الخط العربي يعتمد Cairo والإنجليزي يعتمد Plus Jakarta Sans مع fallback محلي؛ تتطلب خطوط Google اتصالًا بالإنترنت.
- الحركة تشمل reveal أثناء التمرير، hover transitions، progress line، scan effect في الـ hero، وmicro-interactions للأزرار والبطاقات، مع دعم `prefers-reduced-motion`.

## تصنيفات الماركات

صفحة `car-categories.html` تعرض مجموعات كورية ويابانية وأوروبية وصينية مع لوجوهات محلية عند توفرها وfallback بصري نظيف للماركات التي لا يتوفر لها ملف SVG مناسب. العرض مرجعي لفئات موجودة في السوق المصري ولا يعني شراكة أو اعتمادًا رسميًا.

اختيار المجموعات راعى مؤشرات ترخيص وسوق حديثة وصفحات ممثلين محليين، منها بيانات يوليو 2026 المنشورة عن الماركات الجديدة المرخصة في مصر، وبيانات سوق السيارات حتى يوليو 2026، وصفحات Toyota Egypt وGB Auto وJetour Egypt. راجع المصادر قبل أي تحديث تجاري مستقبلي.

## إضافة صور Gallery / من أعمالنا
- الملف البرمجي المباشر لإضافة الصور هو `js/config.js` داخل الكائن `imageAssets`.
- تم استبدال صورة الهيرو بمعرض أعمال أفقي قابل للتمرير بعنوان «من أعمالنا».
- صور المعرض داخل `imageAssets.gallery` — أضف المسارات بالترتيب داخل المصفوفة. يفضّل لكل تصميم صورة طولية أو مربعة حسب التكوين، وسيقوم الموقع بملاءمتها تلقائيًا داخل بطاقات المعرض وفتحها بالحجم الكامل.
- المعرض البصري الثاني القديم محفوظ مستقلًا داخل `imageAssets.visualShowcase` ولا يتأثر بصور Gallery الهيرو.
- ملفات الصور نفسها توضع داخل `assets/images/`، ثم تكتب المسار النسبي مثل `assets/images/work-01.webp`.

## أهم الملفات

- `index.html` وباقي الصفحات: صفحات الموقع المستقلة.
- `css/site.css`: ملف CSS الوحيد المستخدم، ويحتوي المتغيرات والمكونات والتخطيطات وقواعد الهاتف والتابلت والهيدر والفوتر.
- `js/main.js`: الهيدر، الفوتر، اللغة، النماذج، التصنيفات، والحركة.
- `js/config.js`: اسم المركز، اللوجو، بيانات الاتصال، ومجموعات الماركات.
- `locales/ar.js` و`locales/en.js`: النصوص العربية والإنجليزية.
- `assets/brands/`: أصول اللوجوهات المحلية.

## ملاحظات التنظيم

- الموقع Static متعدد الصفحات؛ كل صفحة HTML تحمل `data-page`، بينما `js/main.js` يبني الهيدر والفوتر ومحتوى الصفحة المشترك.
- لا توجد خطوة Build أو Framework؛ التشغيل المباشر عبر `python3 -m http.server` هو المسار المعتمد.
- أي تعديل بصري عام يوضع في `css/site.css`، وأي نص أو رابط خدمة يوضع في `locales/ar.js` و`locales/en.js`، وأي بيانات اتصال أو ماركات توضع في `js/config.js`.
- شريط الهيدر يستخدم سطرًا أفقيًا واحدًا قابلًا للسحب على الهاتف والتابلت، مع إخفاء شريط التمرير بصريًا؛ القواعد النهائية في آخر `css/site.css` هي المرجع الوحيد لتجاوب الهاتف والتابلت.

## الإصدار ومصدر المشروع

- رقم الإصدار المعتمد لهذه الحزمة هو `1.0.0` كما هو موضح في ملف `VERSION`.
- توجد مؤشرات توافق مع Manus في `app.config.ts` (رابط شعار على نطاق Manus CDN) و`manus-routes.json`، لكن الموقع نفسه Static Vanilla ولا يحتوي على SDK أو حزمة تشغيل خاصة بـ Manus؛ لذلك هذه الملفات مؤشرات مصدر/تكامل وليست شهادة تشفيرية تثبت الملكية وحدها.

## النماذج

النماذج تتحقق من الحقول محليًا وتفتح رسالة WhatsApp مُعبأة ببيانات الطلب. لا تُرسل الرسالة إلا بعد أن يراجعها العميل ويضغط إرسال في WhatsApp، ولا يخزن الموقع بيانات النموذج. رقم WhatsApp والعنوان والهاتف وساعات العمل مضبوطة في `js/config.js`؛ البريد وروابط التواصل الاجتماعي ما زالت اختيارية.

## التشغيل التجاري

راجع حقوق استخدام الصور واللوجوهات قبل النشر التجاري. قبل الإطلاق أدخل بيانات التواصل الحقيقية، ثم حدّد `productionUrl` في `js/config.js` وأضف روابط canonical وOpen Graph URL وSitemap مطلقة بعد معرفة الدومين النهائي. ملف `sitemap.xml` الحالي قالب مسارات فقط وليس جاهزًا لإرساله لمحركات البحث.


## ما تم تحسينه في هذه النسخة
- ربط نماذج الحجز وقطع الغيار والبيع والتواصل برسالة واتساب مُعبأة، مع رابط احتياطي ورسالة واضحة عن خطوة الإرسال داخل واتساب.
- تحويل حقول نوع الطلب وفئة السيارة والماركة إلى قوائم، وتحسين أنواع الحقول والتحقق والحقول الإلزامية.
- إضافة صفحة بيع السيارات إلى التنقل الرئيسي وإزالة طلبات الصور غير المتوفرة لشعارات الماركات (مع إبقاء بديل الحروف).
- إضافة أوصاف فريدة للصفحات، وبيانات مشاركة اجتماعية، وتحديث العنوان والوصف حسب اللغة والصفحة. لم تُضف canonical أو sitemap مطلقًا لأن الدومين غير محدد.
- إنشاء نسخة WebP محسّنة للشعار، واستبدال صورة الهيرو بمعرض أعمال قابل للتمرير.
